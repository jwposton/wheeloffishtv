<objective>
Expose the prune audit trail (PRUNE-03, D-16/D-17/D-18) without any new UI. Record a `manual_removed` event when the operator removes a row via the existing DELETE endpoint, and embed the most recent prune events in the playlist detail GET as `recent_prune_events[]`. No new endpoint or auth surface is added — the embed reuses the existing ownership gate `_get_owned_playlist` (D-19/D-12). The SPA is unchanged; Phase 11's diagnostics modal may consume this payload later.

Purpose: Operators can audit prune decisions (reason + timestamp) via the existing playlist detail API. Material events only (auto_pruned from 10-03/10-04, manual_removed here) — no per-tick logging (D-17).
Output: `PruneEventResponse` schema + `recent_prune_events` field; `manual_removed` audit in `remove_playlist_row`; events query in `_playlist_to_detail`; integration tests.
</objective>
