## Phase Goal

**As a** self-host operator, **I want to** configure named playlists with per-series ordered/disordered modes and episode count N, **so that** the nightly builder can generate deterministic mixed-TV output without DB or API coupling (Phase 5 orchestrates persistence).

<objective>
Wave 2 — Implement the ordered (serial-from-resume) picker. One slot for an ordered row produces one block: a single episode by default, or a contiguous multipart-forward block (D-07). Cursor state is per-row, mutated only by the picker itself, and reusable across consecutive ordered slot allocations within a single rebuild.

Purpose: Lock PLT-05 serial semantics with explicit, test-first behavior so Wave 3 builder can compose ordered + disordered without surprises. Inherit Phase 2 resume + ordering as the single source of truth.
Output: `core/playlist/ordered.py`, `tests/unit/test_ordered_picker.py`.
</objective>
