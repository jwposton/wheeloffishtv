## Phase Goal

**As a** self-host operator, **I want to** trigger episode/season/series watch-state updates through first-party API routes, **so that** Library and playlist detail screens can perform consistent provider-backed actions.

<objective>
Expose backend API routes for watch-state mutations that enforce auth/ownership and return actionable outcomes for UI parity flows.

Purpose: Bridge provider adapter capabilities from Plan 09-01 into user-facing API contracts.
Output: Catalog route handlers and API tests for mutation flows and failure handling.
</objective>

## Grey Area Decisions (Locked)

- **Response envelope**: Use a **mandatory fixed schema** for all watch mutations (episode/season/series, watched/unwatched):
  - `status`: `succeeded | partial | failed`
  - `scope`: `episode | season | series`
  - `updated_count`: integer
  - `failed_count`: integer
  - `failed_ids`: list (may be empty)
  - `error_code`: nullable (`auth | forbidden | not_found | provider_error`)
  - `message`: string
